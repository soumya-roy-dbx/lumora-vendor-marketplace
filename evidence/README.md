## Notes for the reviewer (what happened along the way)

- **Evidence was captured as a non-finance user.** The capturing user is not in `lumora_finance`,
  so contract cost reads as `NULL` everywhere (SQL, metric views, Genie, agents) — that is the
  column mask working. `sql_evidence.md` shows the registered masks and the `is_member` check.
- **The eval gate caught a real governance leak.** An earlier eval run scored correctness 0.5–0.75
  (visible as older runs in `mlflow_evaluation.md`). Two causes, both fixed:
  1. the eval's expected answers were hard-coded from an older data snapshot → expectations are now
     derived from the governed tables at run time (`notebooks/08_mlflow_eval.py`);
  2. the judge found the agent quoting contract **cost** that was masked in the tables — it came from
     generated contract documents reachable through Vector Search. Cost is now kept out of all
     unstructured documents (`notebooks/03_generate_vendor_docs.py`), the index and Knowledge
     Assistant were re-synced, and the fresh eval scored 1.0 / 1.0 / 1.0. `sql_evidence.md` no longer
     contains dollar amounts in any document, and `agent_bricks_responses.md` contains none.
- **Transient failures on earlier runs** (before the runs committed here) were fixed in code, not
  retried away: the OpenAI client missing on serverless (`10_data_quality`), a `protobuf` downgrade
  from `databricks-vectorsearch` crashing the kernel (`04_vector_search` now uses the built-in SDK),
  and a hard-coded experiment name (`08`/`09`).
- Bundle **development mode** prefixes some names (`[dev soumya_r]`, `dev_soumya_r_lumora_guarded_llm`).
